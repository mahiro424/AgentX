# AgentX 兼容性验证计划 v0.4

日期：2026-09-07。当前状态：G0/G1 有限核心验证已结束，M1 产品实施计划已批准，下一步先完成文档与正式 Issue 门禁。Flash 真实工作、同线程续轮、文本轮停止与执行后历史读取的范围见[核心兼容报告](../validation/AgentX_Compatibility_Evidence.md#evidence-g1)。本文件保留完整 V1 的验证清单，不要求在 M1 开发前重做整套前置测试；系统变更、上游补丁与远程写入仍单独授权。

授权沿革：首轮仅允许无密钥 G0，[首轮失败报告](../validation/AgentX_Compatibility_Evidence.md#evidence-g0-first)保留。用户后续批准以真实执行与产品控制为核心，共享用户技能改为非阻断来源观察，暂不推进隔离补丁。本轮仅使用用户提供的 Key，通过关闭回显的运行时输入交给验证进程；不读取其他应用凭据，不保存 Key。调用许可仅限 Flash，不代表其他模型也获准测试。

## 1. 目标与执行边界

以最小真实工作链验证“AgentX 产品侧 → Codex App Server → DeepSeek → 工具 → 文件或软件结果”，尽早识别无法通过公开接口实现的能力。不是先建聊天演示，也不是一次建设完整产品。

执行前另外提交具体文件、依赖版本、测试目录、调用方式、可观察结果和清理方案。涉及真实 DeepSeek 请求，须由用户在受控本地入口提供凭据并批准消耗；不要求把 Key 粘贴到对话，不读取既有其他应用凭据。

只能使用专属测试目录和合成或脱敏材料。不得改用户项目、全局 Codex 配置、已有浏览器 profile 或系统级环境变量。Windows 沙箱准备若需要系统变更或提权，应单独说明并获授权，不以全局提权替代测试。

门禁只阻断与当前目标直接相关的行为。G0 共享技能、插件后台连接和执行前历史读取失败可分别保留观察/限制，不阻断 G1；不能仅凭无历史就推断失败原因。G1 真实执行后 `includeTurns:true` 已返回 3 轮，但跨进程恢复未验证。真实模型协议、工具执行、审批拒绝与停止失控仍属于核心失败。允许发现共享技能不等于允许任意额外工具执行，也不是修改正式产品默认共享策略。

执行路线以已批准的 [M1 计划](AgentX_M1_Implementation_Plan.md) 为准：复用已测 G0/G1 结果，不再将全量 G2 设为拆 Issue 或实现外框的前提。G2、G6 与 G7 的 M1 必需部分随相应产品切片验证，失败阻断关联行为；G3–G5、完整备份升级和安装器留给相应 V1 功能，未完成不宣称完整首版。

## 3. 逐项验证方法

### G0 原生运行与协议

- 记录 Windows 版本、架构、引擎版本与 SHA-256；选定官方来源，不执行可漂移 latest。
- 核对实际二进制与固定官方发布产物的校验记录；检查产品没有引擎内部源码依赖、私有状态写入或未登记补丁。零补丁时记录数量为零；存在补丁则必须有批准记录、顺序和对应测试，不用只有版本字符串证明未修改。
- 从目标二进制生成 TypeScript 与 JSON schema，标记稳定面和实验面；比较文档中的必需接口，不假设网页和二进制一致。
- 专属进程 stdio 完成初始化，分离 stdout 协议与 stderr 诊断；验证中文、空格路径。
- 检查实际 CODEX_HOME、SQLite 目录覆盖及用户/项目/共享配置来源。测试应使用专属临时数据根，不建立正式用户目录替代批准流程。
- 来源检查以准确记录为通过标准；共享技能存在时记录路径、启用值及严格隔离不满足，不以此终止 thread/start 等独立接口检查。历史严格隔离实验的失败证据保留，不改写为历史成功。
- 人工制造启动失败、协议不匹配和残留进程，确认不会启动第二个重复执行实例或批量清理其他程序。

### G1 模型与工具闭环

- 分开验证 GET /models 拉取、每模型最小连接测试、真实 Responses 请求与 Agent 工具闭环；列表拉取成功不能替代后三项。确认无 OpenAI 登录依赖，连接测试不带用户材料。
- 验证流式文本、函数工具调用、工具结果匹配、后续推理与权威终态。
- 在测试项目让模型读取现状、修改至少两个关联文件、运行一个真实验证命令；检查文件内容、退出码与最终说明。
- 验证目标模型的 apply_patch 调用格式，不只测试普通文本。
- 测试错误 Key、额度或服务错误、限流、流中断、工具参数错误；错误归因清楚，已发生副作用不因请求重试被重复执行。
- 分开检查真实 usage、缓存 usage 与估算；缺字段显示未知，不能伪造零值或复制订阅额度。

### G2 权限与凭据

- 分别测试默认批准、拒绝、完全访问的实际效果；校验模式变更生效点，活动轮不得悄悄扩大。
- Windows 沙箱 setup 应答与完成结果分别核对，至少一次真实文件与命令限制测试；setup 成功不等于隔离行为必然成功。
- 自动审查独立验证当前版本和 DeepSeek 组合；不通过则记录不可用。
- 使用合成凭据标记检查普通页面、日志、环境输出、配置文件和备份不泄漏；设置默认隐藏，仅用户显式眼睛操作可受控临时显露，关闭、离页、窗口失焦后隐藏并清理。检查无每字符覆盖、掩码回写、空编辑框误删、保存失败假成功及非产品窗口调用。不要打印真实 Key 做泄漏验证。
- 检查引擎需要的凭据不会因默认环境继承进入无关 shell 或 MCP。加密不可用、错误用户解密和更新失败必须显式报错。
- 浏览器和原生 helper 单独验证授权；路径链接、跳转、下载、文件选择器与可执行代码入口不能绕过产品声称的边界。
- 若无法强制某个边界，明确收窄能力或请求实际工具范围授权；不能静默退为全访问。

### G3 文件与办公

- 合成 DOCX：提取内容、按要求改写为新文件、重新打开验证；原件哈希不变。
- 合成 XLSX/CSV：含中文、空值、日期与公式；执行清洗、汇总和生成结果，独立核对预期数值及公式语义。
- 合成文本 PDF：提取与摘要；扫描 PDF 作为不同能力处理，不把空提取当成功。
- 检查同名冲突、文件占用、目录无权限、格式不支持、转换中断和半成品；产物不可用时明确标记。
- 在已有人工改动的代码项目测试差异；覆盖模型 patch、shell 生成文件、未跟踪文件及并行人工编辑，不将已有内容覆盖或错误归因。

### G4 浏览器与跨软件

- 使用专属浏览器 profile 与本地测试网页，读取结构化数据，生成表格和报告，在目标软件打开。
- 验证下载目标、重定向、弹窗、登录等待和页面失效；不接管用户已有浏览器登录态。
- 工具必须报告实际目标、操作与结果。只通过网页截图或打开 URL 不算跨软件闭环。
- 验证网页恶意文本不会自动扩大权限；Playwright 的来源过滤不能当作完整安全隔离。

### G5 桌面与视觉

- 选定可观察的 Windows 测试应用和合成文件，记录这是验收样本而非产品永久软件白名单。
- 单独验证视觉模型对截图的实际理解；普通文本模型输入图片时应显示不支持，不接受占位文本假通过。
- 验证读取窗口、聚焦、输入、保存、重新打开核对；覆盖高 DPI、窗口移动、目标消失和过期截图。
- 用户停止后不得继续发起新的桌面动作；正在执行且不能撤销的动作必须说明最终事实。
- 测试锁屏、UAC、高权限窗口和失去桌面会话，明确能力边界。不能通过把整个 AgentX 永久以管理员运行来宣称问题解决。
- 具体桌面库只有通过以上检查后才锁定；默认优先复用成熟接口，不重建视觉控制模型或 Agent 循环。

### G6 状态与恢复

| 用例 | 故障注入 | 通过标准 |
| --- | --- | --- |
| STATE-START-UNKNOWN | turn/start 发送后丢应答 | 不重复提交，进入核对，副作用次数不增加 |
| STATE-INTERRUPT-ACK | 延迟终态，仅先返回停止应答 | UI 保持停止中，不提前宣称停止 |
| STATE-STALE-APPROVAL | 待审批时断开并建立新连接 | 旧按钮失效，不把旧 requestId 发给新连接 |
| STATE-ARCHIVE-ORTHOGONAL | 失败后检查部分结果、归档后恢复 | 不产生验收记录；失败标签保留，恢复归档不执行 |
| STATE-LATE-TERMINAL | 延迟旧轮完成事件 | 当前新轮状态不被覆盖 |
| STATE-NO-REPLAY | 工具已写文件但记录未同步时重启 | 核对文件与历史，不重放写入或外部提交 |
| STATE-MISSING-HISTORY | 确认无残留执行但历史不可恢复 | 用户知悉后以未确认收尾并释放资源；新工作不伪造继承缺失历史 |
| STATE-CONFIG-REVISION | 测试中换 Key、活动轮关闭连接、旧结果晚到 | 保存与生效分开；旧测试不覆盖新修订，不静默用旧配置执行新轮 |
| STATE-HUMAN-TAKEOVER | 停止应答先到、桌面动作尚未结束 | 未确认前不移交控制；继续显式开新轮、重新观察 |
| G6-TRAY | 最小化、切页面、关闭到托盘 | 引擎不因窗口变化被重建 |
| G6-EXIT | 活动任务退出、进程崩溃、遗留子进程 | 仅处理拥有的进程，未知状态保持可见 |
| G6-STORAGE | 注入写库失败 | 不宣称已保存，不悄悄启动下一任务 |

故障注入只用于测试，不增加生产环境静默模拟或跳过执行的分支。

### G7 包与数据

- Windows 安装、启动、卸载行为在测试环境验证；不把正式发布、签名或购买证书包含在本计划授权里。
- 验证安装资源只读、用户数据可写；无用户 Node/Python 环境时所需运行时与依赖可用，或安装流程明确处理，不静默调用任意 PATH 版本。
- M1 使用内置 node:sqlite，验证目标 Electron 打包环境的真实读写、持久化与事务；同时验证 safeStorage 加解密。不能用开发 Node 的测试代替，也不在失败后静默换驱动或存明文。后续若另提 native addon，须单独评估 ABI 与架构。
- 数据迁移测试覆盖成功、事务失败、旧版本读取新数据拒绝与配套恢复；不通过删库“修复”。
- 引擎升级使用隔离数据副本和固定协议；验证无活动执行时切换，以及引擎/产品数据需要配套回滚的情况。
- 明确备份不含凭据与浏览器登录状态；实际验证恢复后内容完整、Key 需重新设置的提示准确。
- app-shell、workbench、settings 三项规格覆盖两个主要功能界面；按 PRD 状态策略和已确认图稿测试布局、主题、键盘与 Windows 缩放。mockup-driven 不代表仅比截图，不省略真实状态与数据链验证；当前评审图片不是测试通过证据。

## 5. 退出条件与下一阶段

- G0/G1 核心能力失败：暂停相关实现，先修正兼容方案；非阻断来源观察不触发全部暂停。不得将替换引擎或增加协议网关当作默认授权。
- G2 失败：停用不能真实执行边界的模式或工具，说明对已确认范围的影响。
- G3/G4/G5 失败：保留可运行部分的阶段版身份，不宣称完整首版。
- G6/G7 失败：不视为可靠可发布版本。
- 现在按 M1 先同步文档、建立父 PRD/Design/开发 Issues、分拣并合入设计基线，再按依赖实现。M1 所需 G2/G6/G7 随切片完成，其余 V1 清单保留；不将“全量兼容测试完成”作为创建 Issue 的前提。远程创建、提交、推送、PR、合并和发布均分别按授权执行。
