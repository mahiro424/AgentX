## 4. 技术方案与接口边界

### 产品结构

保持 Electron + React + TypeScript、Forge + Webpack，不更换框架：

- Renderer：页面、草稿、消息与状态展示。
- Preload：有限、类型化产品接口。
- Main：本地数据、凭据、项目会话、进程与执行协调。
- Codex 适配：固定版本公开 stdio 协议，不含页面逻辑或第二套 Agent 循环。

修正包入口为 `.webpack/main`；现有 Electron npm 包不等于二进制已落地，M1-01 完成依赖准备及真实打包验证。没有有效桌面行为 RED 时，不把环境启动失败当作完成 TDD 的证据。

### 本地数据

正式默认根目录为 `C:\Users\win\.AgentX`，自动测试使用独立临时目录，不读取正式凭据或真实项目。产品元数据使用内置 `node:sqlite`，无 ORM/额外数据库服务；普通偏好用配置文件，凭据用 Electron `safeStorage` 系统加密。

产品保存项目、会话组织、草稿、发送意图、引擎关联和结果引用；完整执行历史归 Codex，文件系统是内容真相源。M1-01 必须验证打包后 SQLite 与合成凭据加解密，失败阻塞，不私换存储或降为明文。参考：[SQLite](https://nodejs.org/api/sqlite.html)、[safeStorage](https://github.com/electron/electron/blob/main/docs/api/safe-storage.md)。

### 公开产品接口

沿现有 getAppInfo 接缝，按需增加设置/模型、项目/会话、执行/结果三组有限接口。包含配置保存与显隐、模型拉取/选择/测试，目录关联、历史与草稿，执行快照、补充、停止、审批、事件订阅、差异和结果文件打开。

请求与事件关联产品任务 ID、操作 ID 及已确认的 thread/turn/item。Renderer 不接触原始 RPC、任意命令执行或通用文件系统接口；接口和状态分工详见[整体架构](../architecture/AgentX_Architecture.md)。

### 引擎与状态

固定官方 Codex 0.153.4、现有 SHA-256 和对应生成协议，默认零补丁；引擎作为应用资源，不从 PATH 随机选择。复用 G1 配置/关联思路，不搬入自动拒绝审批、固定任务和测试报告编排。

顶层任务串行；另一个任务运行时可浏览、写草稿，不自动排队。`turn/completed` 决定轮次终态，停止应答不等于已停。丢应答、断线、异常退出先核对，不重发任务/审批。历史用固定版本已实测公开读取路径，读取失败不伪装空记录；重开恢复仍需产品验收。共享技能来源作为已知问题记录，不重启隔离补丁、不声称完全隔离。

## 5. 测试与完成标准

每个可观察行为按 RED → GREEN → REFACTOR，不先完成全部测试再集中实现。自动测试覆盖输入、存储事务、配置修订、凭据保护、事件归属、重复提交和错误路径；测试替身仅用于确定性故障验证，不作为真实交付。

真实桌面测试经过 Electron 窗口与有限 IPC，不用浏览器页面冒充。Windows CI 安装锁定依赖、类型检查、构建、无密钥测试，不自动调用 DeepSeek。人工 UI QA 对齐采用图，覆盖深浅主题、960×640/1280×820、键盘/中文输入法、Windows 100%/125%/150% 缩放。

### 现场验收

使用合成小代码项目，不直接试用户业务项目。验收依据为 PRD `ACCEPTANCE-M1`：

1. 配置 Flash，重开应用配置有效。
2. 自然语言要求修复两个文件，实际修改并运行测试。
3. 检查真实差异/退出码/结果，独立重跑，保留人工改动。
4. 同一会话明确续轮，不产生无关联历史。
5. 分别核对审批允许、拒绝和运行中停止的实际副作用。
6. 重开可读已结束任务，异常未决任务不自动执行第二次。

真实验收只人工触发、只调用 Flash；单次最多五个顶层轮次，每轮可能多次请求模型。连接测试另记请求次数；遇阻先诊断，不自动扩大调用。技术查询优先 Context7，不传密钥或私人材料；固定二进制的协议和实际运行结果优先于可漂移网页。

最终交付：可解压双击的 Windows x64 M1 应用包、真实界面截图、自动测试与现场验收记录、已合并工单链路、明确 V1 后续清单。安装器、签名和公开发布不在完成条件内。
