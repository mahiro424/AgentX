## 第一功能：不关联项目也能执行

### 已实现边界

- 空白草稿不创建任务、引擎会话或工作目录。首次有效发送由 Main 分配 `workspaces/<taskId>`，Renderer 不能指定执行目录。
- 任务、执行请求、进程租约、草稿与搜索结果使用可空项目关联；不制造虚假项目。独立会话复用“最近”、置顶、归档、搜索和历史读取。
- 数据库 v12→v13 先一致性备份，再事务重建任务与租约表；提交前执行完整外键检查。失败保留旧库，不清空重建。
- 独立目录拒绝链接或目标变化；续轮使用原目录，目录缺失时不重新造空目录冒充恢复。
- Codex 0.153.4、公开协议、原生审批和唯一执行循环保持不变；本功能没有引擎补丁。

### RED → GREEN 与诊断

1. 非项目首发单测首先因 `projectId: null` 被拒绝而失败；贯通类型、存储、租约和执行目录后通过。
2. 非项目目录落库增加拒绝任意目录的行为测试，先确认失败，再增加 Main 落库校验；错误不留下无法读取的任务。
3. Electron 初始测试确认旧包发送按钮禁用。后续验证夹具曾同时注入另一套协调服务，且模拟“模型已配置”却没有初始化产品数据库，出现输入/刷新时序超时；保留原始失败日志。最终桌面测试只覆盖真实 Renderer、有限 IPC 和 SQLite，协调服务由独立集成测试覆盖，真实引擎由 Flash 验收覆盖。准备数据库而不创建假项目，没有延长输入操作超时或强制点击。
4. v12 损坏引用用例第一次在构造夹具时被 SQLite 自身外键阻断，不是产品迁移失败。仅在损坏夹具构造阶段关闭外键后，验证迁移拒绝、原库哈希不变、版本仍为 v12、备份可读。
5. 取消置顶的非项目会话原提示仍称“原项目”。经真实悬停操作复现后，修正为回到“最近”分组；项目会话原提示保留。
6. 一次验证编排误将截图进程与原目录打包并发运行，出现 `AgentX.exe` 占用导致的 EPERM，该次打包和截图均记为失败。核对并结束本次自动验证创建的进程后，改为串行重新打包和启动检查；未结束用户窗口，也未用占用期间的截图作为最终证据。
7. 首次全量回归 238/240 通过。两项失败来自 M1 的过期断言：要求先选项目，以及侧栏要求先选择项目的旧文案。按已批准的非项目能力更新断言，同时继续要求无模型配置时禁用发送；不删除用例或放宽凭据、权限检查。
