## 首个检查点：材料表格只读（179559b）

- CSV 使用 UTF-8 严格解码，保留 BOM 后正文、引号/换行、前导零和公式样式文本，不默认转换数值。
- XLSX 保留工作表、稀疏坐标、数值/布尔/日期/错误/文本；公式文本与保存的缓存单列，不运行计算引擎；合并从属格引用主格，不重复计数。
- ExcelJS 4.4.0 与 unzipper 0.12.3 固定依赖，随 Webpack 打包。仅使用本地 Buffer；S3 可选 SDK 不安装，构建保留其缺失时的明确运行错误，不使用空模块替代。
- 解析发生在独立 Electron run-as-node 子进程。Main 只发送核验字节，不传凭据、任意命令或任意 Renderer 路径。最多 2 个并发解析，输入 8 MiB、解压累计 32 MiB、2000 压缩条目、16 工作表、每表 2000 行/100 列、总计 100000 单元格、输出 8 MiB、10 秒超时、192 MiB V8 堆上限；不是 OS 沙箱或全进程内存承诺。
- 主线程退出时请求结束所属解析子进程；真实合成挂起进程通过超时后 PID 已不存在的检查。强杀/断电后的恢复归 M2-05，不能由这一测试冒充已完成。
- 材料登记和预览复用实际路径、打开文件身份、SHA-256、草稿 CAS 与原版本授权；解析后再次核对文件身份。重查不重复启动已知版本解析，也不把旧解析失败改成成功。
- 右侧沿用文件页签，底部工作表可用方向键/Home/End 切换，表格双向滚动，单元格原值/公式及缓存说明可查看。外部变化保留旧视图并标陈旧，关闭返回材料焦点。
- 该只读提交中的表格发送/生成明确阻断并保留草稿，不将只读材料能力冒称 Agent 已经处理。后续接入记录见下文，完整工单仍保留完成门禁。

## 第二个检查点：表格读写工具与产物链路

- `office-reader` 与 `office-cli` 复用同一个 `office-spreadsheet` 解析模块；前者接收 Main 核验字节并由 Main 控制 10 秒预览超时，后者由 Codex 既有命令执行拥有，入口设置 30 秒超时。不将不同调用用途解释成两套 Agent 循环，也不把计时器当作 OS 沙箱。
- CLI 的 `read` 读取真实材料、强制核对 SHA-256，将含工作表/坐标/类型/公式及缓存的 JSON 写入工作目录新文件。`write` 从有限 JSON 内容生成 CSV/XLSX；不加载宏、脚本或任意模块，不在线安装依赖。
- 生成先在内存回读结构，再以 `wx` 新建文件，同名直接失败；错误保留部分文件而不宣称成功。CSV 多工作表和公式拒绝，公式样式字符串提示改用 XLSX，不悄悄改写数值或转义原文。XLSX 公式不重算，缓存与实际重新计算值不混同。仅处理单元格数据，不承诺样式、图表、超链接动作等完整 Office 保真往返。
- 表格材料通过原公开文本输入附带工具用法、路径与版本；首发、续轮、补充仍由原执行服务派发，未增加 RPC 或任意 Renderer 文件访问接口。损坏、变化和未确认发送仍保留草稿，不重发。
- 真实文件变化登记 CSV/XLSX 产物，版本仍绑定 task/thread/turn/operation；按授权 ID 重新解析并复用右侧工作表。普通文件扫描限 1 MiB，CSV/XLSX 扩到 8 MiB；总量仍 32 MiB，大表基线保存指纹而非大量正文，基线读写校验同步扩展。
- 结果按钮按文件类型标注预览，版本列表改称“已检查文件版本”；不新增页面。表格预览明确可读不等于业务结果已验证，中断/失败可能是部分产物。
