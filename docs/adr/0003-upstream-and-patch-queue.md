# 默认零补丁并以最小补丁队列跟随上游

状态：已接受方向，具体实现尚未验证。日期：2026-09-07。

AgentX 优先使用固定版本、未经修改的官方 Codex 二进制。引擎版本、校验值、生成的协议类型和兼容性结果共同组成发布基线；产品不得直接跟随可漂移的 latest 标签。升级优先修改产品适配层与公开配置，不建立长期业务分叉。

只有公开接口不能满足必要需求且另获批准时，才建立最小 Patch Queue。每个补丁记录上游基线、原因、实际差异、测试、维护责任、上游关联与移除条件；不允许将 UI、产品账户、计费、任务分类等产品业务写入引擎。补丁能被上游能力取代时删除，不继续积累。

相比深度 fork，这一方案降低升级合并成本，但不能保证任意未来能力都无需上游变化。升级失败保持当前版本；数据格式已迁移时，不能只切旧二进制，必须验证兼容或恢复配套的一致性备份。应用安装包与用户数据分离，活动执行期间不热替换引擎。

操作顺序与回滚约束见[整体架构](../architecture/AgentX_Architecture.md)，验收见[验证计划](../plans/AgentX_Compatibility_Validation_Plan.md)。官方依据：[版本对应协议生成](https://learn.chatgpt.com/docs/app-server)。
