## 1. 架构目标与不变量

M2 进度补充（2026-09-09）：M1 最终 PR #19 已合入，M2-01 会话组织与搜索已经 [PR #29](https://github.com/mahiro424/AgentX/pull/29) 合入 m2。用户批准后续按 [M2 计划](../plans/AgentX_M2_Implementation_Plan.md) 分别贯穿文本、表格、文档的材料—产物—预览—续改链路，异常收尾仍为 M2-05。M2-02 分支已接通非项目任务与持久材料执行检查点；独立文本预览及其后续切片尚未完成，具体证据见 M2-02 验证记录，不把拟定库/工具写成已验证能力。

- 产品功能优先在外框实现；引擎是可替换版本的黑盒进程，不是供产品随意调用的内部代码库。
- 一个规划与执行循环：由 Codex 负责。产品不创建第二套 Planner、调度 Agent、审批 Agent 或完整会话记忆库。
- 一个事实维护者：产品元数据归产品，执行历史和 turn 终态归引擎，文件内容归实际文件系统；目标是否满足由用户检查判断，不建立产品验收状态。
- 界面表现、进程存活、执行状态与结果检查行为分开。RPC 应答不等于工具成功，工具成功不等于任务目标完成。
- Windows 原生执行是首版基线；不默认要求 WSL、Docker 或管理员运行整个产品。
- 当前已批准 M1 本地实施，正式产品默认使用用户目录下 `.AgentX`；自动测试始终使用独立临时根。远程 Issue/标签、Git 操作、PR 与合并分项授权；真实模型验收由用户主动触发且只用 Flash，不因实施批准自动批量调用。系统变更与迁移既有用户配置不在本轮范围。

## 2. 技术基线

| 领域 | 基线 | 约束 |
| --- | --- | --- |
| 产品语言 | TypeScript | 不为概念一致而重写引擎；外部工具可用其适合的语言 |
| 界面 | React、CSS 变量与通用组件 | mockup-driven UI，页面行为在 PRD，图稿经确认后形成视觉基准 |
| 桌面与构建 | Electron、Electron Forge、Webpack + TypeScript | 固定依赖版本，包体与资源占用纳入验证 |
| 产品后端形态 | 本地模块化单体 | Main 提供产品服务，不启动通用 HTTP 业务服务器 |
| 数据 | 内置 node:sqlite、显式版本迁移；普通偏好配置文件；safeStorage 凭据加密 | Main 单一产品写入者；不引入 ORM、数据库服务或明文凭据兜底 |
| 引擎通信 | 专属子进程 stdio | 类型从目标二进制生成；不用私有数据库作为接口 |
| 模型 | DeepSeek 自定义 provider、Responses API | 无 OpenAI 登录依赖；不建设协议转换网关 |
| 工具扩展 | 公开 MCP、Skills；按需验证其他接口 | 实验接口必须显式门禁，不伪装稳定能力 |
| 质量 | 单元、协议集成、真实 Electron 桌面端到端、人工验收 | M1 与 M2-01 有产品证据；其余切片独立验收，启动失败不能计作行为 RED |
| 发布 | M1 为可解压双击的 Windows x64 包，固定引擎资源；V1 安装器后续 | 签名、外部发布、联网更新执行均需另行授权 |

### 2.1 M1 的现有工程接缝

M1-01 的 Main/Preload 暴露 `getAppInfo`、`getPreferences`、`savePreferences` 三个有限产品接口，校验产品窗口、主 frame、规范 URL 及载荷；Renderer 实现共享侧栏、真实空工作台和通用外观偏好。Forge 入口已修正为 `.webpack/main`，Electron 44.2.0 二进制已落地，并已启动真实打包窗口。

实现基于正式 Issue #6 和已合入 m1 的 PR #12 / #13；历史 AX-001 不替代门禁。SQLite 和 safeStorage 的合成数据探针已经在打包 Main 的 Node 24.20.0 中验证事务、重开读取与跨进程解密，M1-01 的 CI 与视觉确认随后完成。

M1-02 通过 `ModelService` 与有限产品桥完成配置、系统加密密钥、模型目录、选择与逐模型连接测试；只有 Flash 可被测试或选作执行模型。自动测试用合成凭据与受控响应，不能替代真实模型任务验收。具体证据见[模型设置记录](../validation/M1-02_Model_Settings_Validation.md)。

M1-03 的 `ProjectService` 通过原生单目录选择获取路径；Renderer 不提交任意路径。`realpath` 解析后精确去重，名称只改产品记录，目录可用性读取失败不删关联。新增 `getWorkspace`、`chooseProject`、`renameProject`、`onWorkspaceChanged` 四项有限桥，沿用窗口/frame/URL 校验。`useWorkspace` 隔离列表读取错误和关联操作错误，旧读取不能覆盖新快照或抹除操作失败；原有外框加载项目/会话侧栏和名称编辑弹层。

`storage/database.ts` 统一维护产品 SQLite，不新增第二个数据库 owner。前三个版本为模型目录、测试和未决 Key 保存标记，v4 为项目，v5 为任务列表元数据；v6 为发送意图，v7 为按未关联/项目/任务隔离的草稿，v8 增加意图与精确 turn 的绑定，旧记录不按时间猜测。M1-06 升到 schema 9，新增 `runtime_leases`：保存实例/操作/任务/项目关联、引擎 PID/父 PID/完整创建时间/映像路径，以及可能派发工作、根进程关闭、完整回收记录；不保存 Key、环境变量或命令行。首次任务与意图原子写入，发送失联原子进入待核对；草稿修订防旧写覆盖。旧版迁移前留 `agentx.before-v9.<uuid>.db` 一致性快照，既有备份不动，迁移整体事务提交，失败不删库重建；这不是 V1 备份恢复产品功能。

M1-06 在已校验固定资源的执行引擎握手后核验 Windows 进程身份，任何任务派发前持久化归属。正常退出与续轮替换共用「权威轮次终态 → 核对/回收已知后台终端 → 等待本实例子进程关闭 → 记录释放」链路。裸关闭只记根进程关闭，不把它当作后台全部退出；未释放记录跨重启继续阻止新执行。只读历史连接不派发任务，不占用执行归属记录。PID 会被复用，异常核对再次比较完整身份，不允许按名字或单个 PID 结束进程。准备失败且无发送意图时可回收后重试。

`getReconciliation({taskId})` 是新增的有限产品只读桥：读取产品任务/发送意图/引擎归属、实际 Windows 进程与公开 `thread/read`。只精确认领有意图绑定的 turn，不用最后一轮或时间近似猜测；查询失败、PID 复用、历史失败与读取期间元数据变化分别展示。冷连接不获取模型 Key，仍可能写引擎自身索引，不承诺磁盘零写入。没有 thread 的准备记录也能显示诊断；全局遗留归属不依赖侧栏存在原任务。核对不重发、不自动回答审批、不清锁；即使根进程消失且历史为 interrupted，后台仍未验证时继续保持未知。M1 不提供通用人工清锁/恢复执行功能。

`createTaskRecord` 是 Main 存储接缝，不暴露给 Renderer。M1-03 生产界面只读实际产品记录，不播种示例；测试通过合成记录验证读取、活动时间和重开。持久化非终态仅为旧观测，读取时投影 `reconciling`，不伪装为活跃引擎。M1-04 负责接入真正的执行生产者与已核对活动投影，M1-05 负责引擎历史正文；见[项目入口验证记录](../validation/M1-03_Project_Sessions_Validation.md)。

### 3.1 Renderer 与 Preload

- Renderer 不启用 Node.js 集成；启用 contextIsolation 和 renderer sandbox，不把这些设置当作引擎文件权限。
- Preload 逐个暴露类型化产品方法；不暴露 ipcRenderer、任意文件读写、任意 shell 执行或整个 Main 对象。
- IPC 校验调用窗口、载荷类型、路径和请求所属任务。Renderer 自报 taskId 不构成授权。
- Renderer 默认不接收已保存 Key；写入经受控凭据接口完成，掩码不作为实际值提交。仅设置页的显式显隐动作可以通过有限 IPC 临时取得明文；离开页面、窗口失焦或关闭眼睛即隐藏并清理临时值，不进入通用状态持久化、日志、剪贴板或诊断。此入口必须校验产品窗口和调用来源，不能由远程页面触发。
- Markdown、文件预览、网页内容按不可信内容处理；脚本禁用或严格隔离，链接和文件打开经 Main 校验。
- 远程网页不能加载到具有产品 Preload 权限的窗口。预览与浏览器工具使用独立权限上下文。

### 3.2 Main 与工具进程

Main 管理应用单实例、窗口、托盘、产品服务、SQLite 生命周期和引擎连接。轻量产品逻辑在 Main 模块运行；耗时文件转换、浏览器与桌面操作放到受管理的独立进程，不阻塞窗口消息循环。

首版只允许一个用户顶层任务处于发送、执行、审批等待或状态核对阶段；其他任务仍可浏览与编辑草稿，不自动排队执行。该策略不重写或限制引擎内部 Agent 循环，目的在于减少共享工作区、工具配置和桌面资源冲突。未来多任务并发作为单独变更评估，不提前建设调度平台。

关闭主窗口保留 Main 与其子进程；主动退出走停止与回收流程。仅回收本实例确认拥有的进程，不按进程名批量杀死 node、浏览器或 codex。Windows 子进程树清理、意外退出与遗留进程检测必须经过真实验证；未确定遗留执行状态时阻止自动重启同一工作。

工具独立进程用于生命周期和故障隔离，不自动提供 OS 安全隔离。高权限应用、UAC、安全桌面、锁屏和断开的远程桌面属于实际能力边界，不能通过错误吞没或全局提权解决。

## 4. 模块职责与依赖方向

以下是逻辑模块，不要求每项成为独立包或服务。

| 模块 | 拥有的数据或行为 | 不得承担 |
| --- | --- | --- |
| 项目与任务服务 | 本地档案、目录关联、标题、置顶、归档、草稿 | 引擎会话历史和规划循环 |
| 执行协调模块 | 产品发送意图、关联 ID、资源占用、状态投影 | 自行决定模型下一步调用哪个工具 |
| Codex 适配模块 | 进程连接、生成类型、RPC 配对、事件归一化 | 产品页面逻辑、修改引擎私有状态 |
| 权限模块 | 产品模式映射、真实生效信息、审批展示关联、工具授权 | 用提示词代替权限执行；独立审批 Agent |
| 工具管理模块 | 已配置工具、来源、启停、健康、授权与进程归属 | 插件市场、动态下载任意未审计程序 |
| 文件与结果模块 | 产物引用、变化清单、比较、打开、检查证据 | 将未知变化归因于 Agent；全盘自动索引 |
| 数据模块 | SQLite 事务、迁移、一致性备份 | 直接操作 Codex 私有数据库 |
| 凭据模块 | 系统加解密、替换、有限供给与设置页受控临时显隐 | 普通日志、普通页面或后台无操作明文回显 |
| 诊断模块 | 脱敏事件、错误码、版本、可导出诊断 | 默认上传日志、保存无限量原始工具输出 |

依赖从界面指向产品契约，从产品服务指向适配器和数据模块。协议生成物只由 Codex 适配模块消费；Renderer 只接收产品 DTO，不随上游字段变化到处修改。首版仅定义 Codex 适配器，不创造一个支持未知未来 Runtime 的插件框架。

### 6.2 产品数据库逻辑实体

下表是 V1 字段责任设计，不等于当前 SQL schema。时间使用 UTC，界面按本地时区显示；M1 实现见 §2.1。M2-01 已增加会话组织修订及可重建搜索。M2-02 分支的 schema 13 已接通任务、草稿、意图、租约与侧栏的可空项目关联，`thread_id` 仍唯一；工作目录由 Main 分配或从关联项目取得，Renderer 不指定 cwd。不提前建设多引擎目录。

M2-02 材料检查点升到 schema 14：`materials` 保存不可变的路径、身份、类型、大小与 SHA-256 记录；`drafts.material_ids` 与文本共用 CAS 修订；`input_materials` 绑定发送/补充的 operation、task、已知 turn、材料版本及应答确认。首发和续轮关联在既有意图事务内保存，补充应答不确定时保留未确认关联，不自动重发。迁移前写 `agentx.before-v14.<uuid>.db` 一致性备份，旧备份不动；v12/v13 有数据升级和损坏引用拒绝已有测试。

文本材料当前限 TXT/Markdown、UTF-8、单文件 1 MiB、每个草稿 16 项；图片粘贴最多 8 MiB/项并保存到 `materials/clipboard`，图像输入仍阻断。普通文件只保存引用，不复制原件；目录不自动遍历。提交前再次核验身份/哈希，经公开文本输入交给 Codex 的现有本地工具实际读取，不把登记状态当作引擎已读证据。独立文本预览与结果版本标签尚未接通，工单 #22 保持进行中。

| 逻辑实体 | 最小内容 | 约束 |
| --- | --- | --- |
| 本地档案 | profileId、可选昵称、创建时间 | 首版一个档案，不是认证系统 |
| 项目 | projectId、显示名、规范化目录、创建时间 | 目录去重考虑 Windows 大小写、链接和重定向；缺失不删除历史 |
| 任务 | taskId、可空 projectId、标题、置顶、archivedAt、threadId、engineHomeId、lastActivityAt | threadId 绑定成功后才写入；约束引擎目录加 threadId 唯一 |
| 草稿与发送意图 | taskId、clientOperationId、类型、阶段、必要待发送输入、已知 turnId、可选人工核对结论与时间 | 保存未完成操作；正常确认进入引擎历史后移除重复正文；异常收尾保留最小核对事实，不是永久聊天副本 |
| 材料引用 | materialId、草稿作用域/修订、Main 核验的路径/身份、类型、读取版本、使用它的发送意图 | 与草稿 CAS 一致保存；同轮使用的版本不随草稿编辑改变；不把正文持久化为另一套会话历史 |
| 结果引用 | resultId、taskId、可空 turnId、可空 clientOperationId、绝对路径、类型、可用状态、验证摘要 | 至少有一个可核对的轮次或操作关联；文件是内容真相源，缺失不能假装可打开 |
| 本地迁移版本 | schemaVersion、迁移时间 | 产品版本兼容范围检查先于正常读写 |

最近观测的引擎状态只作为带观测时间的可重建投影，不作为启动后的权威执行状态。可检索的可见正文仅保留可重建投影。完整消息、推理、工具原始输出继续由引擎持久化；不写另一套 event-sourcing 日志替代引擎。

SQLite 使用单一产品写入者，耗时操作不得长时间占用事务。提交产品变更与发送引擎命令无法形成跨进程原子事务，必须通过发送意图和状态核对处理，不宣称 exactly-once 执行。

├─ cache\                     可重建预览、缩略图与 search.sqlite 文本检索投影

config.json 保存 provider.enabled、selectedModelIds、activeModelId、credentialRef 与 configRevision 等非敏感设置，不存密钥或第二份工具运行历史。最近检查记录绑定配置修订和模型 ID，存于产品元数据；不是永久可用保证。浏览器 profile 含登录状态，不在普通诊断或缓存清理范围。用户项目原件留在原位置；不强制在每个项目创建 .AgentX。

M1 按需创建配置、产品数据库、加密凭据、必要脱敏日志和独立引擎数据目录；不预建浏览器、备份、搜索索引、办公工作区或技能管理体系。M1-01 的打包探针用隔离根和合成凭据，M1-02 才接真实设置；自动测试不读取正式 `.AgentX`、真实 Key 或用户项目。

### 6.4 配置加载与凭据

1. Main 创建专属子进程环境，不改系统环境变量，也不改 C:\Users\win\.codex。
2. 设置 CODEX_HOME；排查 CODEX_SQLITE_HOME 与 sqlite_home 的覆盖关系并检查生效结果，禁止无意写入其他引擎目录。
3. DeepSeek 使用 model_provider、base_url、wire_api=responses、env_key、requires_openai_auth=false 等目标版本公开配置。Key 不交给内置 OpenAI 登录流程。
4. 凭据仅在引擎需要时解密供给，不写 experimental_bearer_token 明文，不运行厂商修改全局配置的一键脚本。
5. shell 环境按固定目标版本的公开配置生成。M1 复用 G1 已测的 inherit="none" 与最小 set 白名单，排除 KEY/TOKEN/SECRET/PASSWORD 等敏感继承项，不把尚未实测的其他过滤写法冒充基线。引擎所需 Key 不传给执行 shell 或无关 MCP；按产品实际调用路径回归，不能假定引擎会替产品清理。
6. 检查用户共享技能、项目 AGENTS.md、项目配置与链接来源，展示来源和信任状态。独立 CODEX_HOME 不等于屏蔽所有配置发现；不自动导入别的产品或用户配置。
7. Key 在提交完整值（失焦或 Enter）时保存，不逐字覆盖；空编辑框或掩码不删除旧 Key。拉取与测试等待保存成功后执行。模型选择、启停或 Key 修改保存为新 configRevision；活动轮绑定旧 effectiveRevision，界面区分“已保存，下轮生效”与“当前轮使用”。需要立即禁用时先停止活动轮。
8. 活动轮结束后，按目标协议应用新配置，必要时重建连接；生效失败保持明确错误和旧轮事实，禁止悄悄用旧 Key、旧模型开始新轮。取消所选默认模型后要求重新选择，不自动换模型。

加密不可用或解密失败时明确报错，不降为明文。产品数据库和普通文档默认不是全盘加密仓库；安全说明必须区分凭据加密与任务内容存储。DPAPI 与环境过滤不防同一 Windows 用户下的任意恶意进程读取，不能将其描述为强应用隔离。

### 6.5 会话检索投影

官方 thread/list 的 searchTerm 仅支持标题片段匹配，不能据此承诺正文检索。产品读取公开 thread/read 历史（含所需轮次），从用户可见消息和可见工具摘要建立 cache/search.sqlite；不读取引擎私有数据库，不索引隐藏推理、凭据、附件全文或整个电脑。

材料检查点对含材料会话仅索引标题和用户要求，并在覆盖提示中明确说明；材料可能被工具输出或助手复述，因此这些会话的助手/工具正文不自动进入索引。已有缓存的非用户命中在查询和定位时同样被排除，不能通过旧索引绕过此边界。无材料会话的原有正文检索行为保持不变。

最小投影字段为 taskId、threadId、turnId、itemId、kind、visibleText、sourceRevision、indexedAt；另存每个会话的已覆盖轮次与更新时间。标题、项目、置顶和归档来自产品元数据，不复制第二套组织真相源。索引不是完整聊天备份，不能作为恢复执行或构造模型历史的依据。

首版接受标准是中文与英文的字面包含匹配、英文不区分大小写；具体 SQLite 查询策略经数据量验证确定，不假定默认 FTS 分词支持中文子串。默认同时检索标题与正文；支持范围、项目及归档筛选，正文结果按 itemId 定位。索引未覆盖、原历史缺失或重建失败时，显示覆盖范围和错误，不把局部结果称为全部。全文索引含任务文本，应与本地历史同等披露隐私属性；清缓存可删后重建，普通备份不包含它。

### 6.6 模型目录、选择与可用性

首版仅配置 DeepSeek。拉取模型列表、选择工作台候选、连接测试、实际 Agent 能力验证是四个不同事实。GET /models 只提供候选 ID；不证明推理或工具可用。仅 provider 已启用且 selectedModelIds 包含的模型进入输入区选择器，一次执行只有一个 activeModelId；多选候选不表示多 Agent 并行。

模型行测试由用户主动触发，以最小无用户材料请求验证连接；清楚说明会产生用量。结果含模型 ID、configRevision、时间、结果和脱敏原因。Key、地址或相关配置修改使旧结果过期，晚到的旧修订结果不覆盖新状态。测试成功仅表示该项测试通过；Agent 工具、图像输入和权限模式仍受各自兼容门禁约束。未测试候选可展示未测，已知失败或不兼容不可伪装可执行。

M1 真实执行和行级测试均仅允许 `deepseek-v4-flash`。其他拉取结果可以保留及勾选，但必须标记本阶段未开放；只在启用且选中时进入工作台候选，并禁用执行，不能通过列表刷新绕过调用限制。权限固定请求批准，不开放自动审查或完全访问。

## 7. 产品与引擎契约

### 7.1 产品请求与事件

产品 DTO 建议包含 clientOperationId、taskId、必要载荷；产品结果包含关联 ID、阶段或可诊断错误。事件包含本连接 connectionEpoch、本地接收序号、已知 threadId/turnId/itemId 和归一化内容。

本地接收序号仅供去重、展示与诊断，不是上游事件重放游标。clientOperationId 只避免本地重复点击，不能让上游天然支持幂等。

错误分为输入、权限、认证、引擎不可用、协议不兼容、工具失败、资源占用、存储失败、状态未知。保留脱敏根因与关联 ID；不要把这些错误转换成统一成功返回值。

M1 在现有 `getAppInfo` 桥上只按需扩展三组有限产品接口：

| 接口组 | 公开行为 | 主要切片 |
| --- | --- | --- |
| 设置与模型 | 保存配置、受控显隐 Key、拉取模型、更新选择、测试模型 | M1-02 |
| 项目与会话 | 选择目录、关联/读取项目会话、保存草稿、提交/读取执行快照 | M1-03、M1-04 |
| 执行与结果 | 补充、停止、回答审批、订阅事件、读取差异、打开结果文件 | M1-04、M1-05、M1-06 |

这些是职责分组，不是额外的通用框架或对外 API 服务。请求由 Main 再校验任务与窗口来源，Renderer 不接触原始 RPC、任意命令或通用文件系统接口。

### 7.2 引擎协议边界

- 启动后先 initialize，再 initialized；握手完成与能力检查成功后才接受执行。
- 类型和 schema 从锁定版本生成。未知可选通知可记录并忽略展示；未知服务端请求、必需字段或终态不能静默跳过。
- thread/start 或 thread/resume 建立会话关联，turn/start 发起一次执行；turn/steer 补充当前轮，必须绑定 expectedTurnId。
- 以 turn/completed 判断一轮结束，以 item/completed 核对具体工具结果。审批解决通知不是文件或命令成功证明。
- 字符流只更新显示，权威完整项覆盖临时拼接内容，避免恢复时重复追加。
- 不把历史分页 cursor 当作事件 replay cursor；断线恢复依据持久化读取与实际状态核对，不重发所有请求。

M1 固定官方 `0.153.4` 与现有 SHA-256、对应生成协议，默认零补丁。历史优先使用 G1 实测的 `thread/read(includeTurns:true)`；其适用范围和错误保留在适配层，跨进程恢复须由 M1-05 实测，不把 schema 存在当作成功。必要时评估公开分页接口属于适配变更，不直接读私有库。共享技能来源问题继续记录，不启动隔离补丁工程。G1 的自动拒绝审批、固定任务和报告编排不得进入生产适配器。

### 7.3 关键链路：启动与执行

~~~mermaid
sequenceDiagram
    participant U as 用户界面
    participant P as 产品服务
    participant D as 产品存储
    participant C as Codex App Server
    participant T as 工具
    U->>P: 提交目标与已选范围
    P->>P: 校验状态、授权、资源占用
    P->>D: 保存任务与发送意图
    P->>C: thread/start 或 thread/resume
    C-->>P: thread 标识
    P->>D: 保存绑定
    P->>C: turn/start
    C-->>P: turn 标识与执行事件
    P-->>U: 展示实际进展
    C->>T: 调用工具
    T-->>C: 真实结果或错误
    C-->>P: item/completed 与 turn/completed
    P->>D: 更新真实终态与结果引用
    P-->>U: 交付结果和验证说明
    U->>P: 检查后用自然语言提出修改
    P->>D: 保存新的发送意图
~~~

这是概念顺序，不承诺所有应答与通知的到达顺序固定。事件可先于请求应答到达，适配器按关联 ID 合并；缺少已知绑定的事件先隔离等待核对，不猜测属于当前页面。

### 7.4 审批与工具授权

引擎审批原样映射为产品可理解的操作和范围；用 connectionEpoch 与 requestId 关联返回原连接，等待引擎后续事件确认。产品工具自身的授权另有明确来源，不能伪装为引擎已批准。

请求批准不等于沙箱内每次写入都需询问；完全访问也不等于软件管理员身份。外部 MCP、浏览器和桌面 helper 不自动被 Codex 沙箱覆盖。允许某项工具前，应验证其执行边界、授权粒度、撤销和停止效果。

对于无法强制执行某项范围的工具，不显示虚假的范围隔离：停用该能力，或明确展示实际更宽的应用控制范围并取得相应授权。不得从受限模式静默退为完全访问。下载、跳转、文件选择器、任意代码执行等绕过路径列入验证。

自动审查只有当前引擎和 DeepSeek 组合通过测试才开放；不通过时仅停用该模式，不建立产品自制审核 Agent。

## 8. 文件改动与办公结果链路

M2-02 先贯穿 TXT/Markdown，M2-03 扩展 CSV/XLSX，M2-04 扩展 DOCX/文本 PDF；每个切片都包含读取、生成适用产物、独立验证、预览、续改，不按前端/解析器/预览分别作水平交付。

1. **准备材料**：原生选择、Preload 拖放路径及图片粘贴进入同一 Main 核验。材料引用按草稿作用域和修订保存；路径、文件身份、读取版本分开记录，移除不删原件。目录只保存引用，不预先扫描全目录。
2. **提交与执行**：首发前核对材料版本及能力，准备发送意图与任务目录。可空项目关联贯穿所有现有任务接缝；输入前不启动 thread。Codex 唯一决定步骤并调用工具；轻量文本可有界异步读取，耗时办公解析/生成放入受管理进程。不将材料内的指令当用户授权，也不绕过真实审批。
3. **产物与检查**：现有结果基线、文件变化和真实工具结果关联到 task/operation/turn；补充产物类型、路径、版本与验证摘要，不建第二份完整执行历史。普通文件是当前内容真相源，工具声称生成或文件存在都不足以证明正确。
4. **只读预览**：Renderer 只提交已授权的材料/结果标识，Main 重查归属和路径后读取。标签同时区分任务、来源轮次/操作、文件版本，防止同路径串轮；预览缓存可重建，外部变化使旧内容标陈旧。打开/刷新/关闭只改变视图，不自动执行任务或释放资源。
5. **同会话续改**：用户检查后提交新要求，沿用原 thread 和既有 continueExecution/发送意图接缝，绑定本次实际材料版本；补充失败保留草稿，不自动改投新轮。重开仅恢复材料引用、视图和已结束历史，不重放操作。

实现落在既有 `shared/contracts`、`preload`、`main/services`、`main/storage` 和 `renderer/workbench` 接缝，按行为增加必要文件，不建立通用资源框架、平行 Agent Loop 或新的历史 owner。上述链路的具体解析依赖和公开工具注册方式随相应格式实施验证。

- 任务开始前建立目标工作区的变化基线。代码项目结合 Git 差异和未跟踪文件；普通目录记录适当的文件指纹与受管理输出。权限不足、超大文件或未覆盖范围必须在检查结果中标记。
- 引擎 fileChange 项、工具产物清单及实际文件变化联合核对，不能只靠模型回答或引擎补丁事件统计 shell 产生的所有文件。
- 基线中已有用户改动保持可见；若同时有人编辑，标记归因不确定。AgentX 内部串行不能阻止外部编辑器写入。
- 文档默认保留原件，输出到明确的新路径；同名冲突不静默覆盖。文件锁定、格式不支持或转换失败显式返回。
- 文档与表格先由本地库提取必要内容，再交给模型；产出后重新打开或解析，并按任务校验内容、公式、表结构等，不能仅检查扩展名。
- 文档、表格、PDF 与图片在产品侧提供只读预览、打开原路径及失败提示；真实编辑仍由工具或用户本机软件完成。执行输出为只读记录，交互终端必须绑定真实受管理进程，公开 command/exec 等接口需验证目标版本，不能把日志视图画成可输入终端。
- 浏览器结构化操作优先使用 Playwright MCP；截图驱动操作要求可用视觉模型。文本型号不支持图像时不得把占位文本当作成功识图。
- 电脑接管先停止并核对相关自动动作；停止确认后才把控制者切换为用户。恢复是用户明确启动新轮、重新观察窗口与文件，不承诺通用暂停检查点。截图显示观察时间与实际控制者，过期图像不作为实时执行依据。
- 产物引用记录路径、生成轮次和验证摘要，不承诺任意外部软件操作都能回滚。回退修改必须重新检查文件现状，避免覆盖后续人工改动。

## 9. 生命周期、恢复与并发

详细转换见[状态流转文档](AgentX_State_Machines.md)。核心规则：

- 窗口关闭进入托盘不改变执行状态；Main 和引擎存活才可能继续工作。
- UI 重建从 Main 拉取当前投影；Main 或引擎重启则先核对持久化历史，不能用旧 UI 状态判断仍在运行。
- 已发送但没收到应答的操作进入结果未知。不得自动重试 turn/start、审批、发送表单或覆盖文件。
- 同一工作目录和桌面资源需排他占用；执行结束、确认失败或中断后释放，状态未知时先核对，不提前交给新任务。
- 已确认无残留执行但历史不可恢复时，按状态契约由用户知悉后以 unconfirmed 收尾并释放资源；原 thread 不可用则显式新建任务，不替换旧任务绑定或假装历史完整。
- 存储失败后不继续宣称“记录已保存”；阻止新执行并展示可恢复错误。引擎已执行而产品持久化失败属于需要核对的部分成功，不回滚伪装原子事务。

## 10. 迁移、清理、备份与升级

### 10.1 产品数据

产品数据库迁移前检查 schemaVersion 和兼容范围，停止写入，生成一致性备份。迁移事务失败保留旧版本或提供显式恢复，不自动删除数据库重建。SQLite WAL 模式下不得把裸复制 agentx.db 当作完整备份；采用驱动支持的一致性备份或停止所有写入并正确处理相关文件。

普通数据备份包含产品设置、会话记录及受管理产物，默认不含 Key、浏览器登录状态、可重建缓存和外部项目原文件；导出界面给出明确清单。外部项目只保存关联，不因产品备份自动遍历打包。DPAPI 密文通常不作为跨 Windows 用户的可移植凭据，恢复后可能需要重新填写 Key。备份不是把活动引擎目录随意复制一遍。

清缓存仅处理已标为可重建的文件；删除任务不删除项目原件。产物清理需要范围预览，递归路径须校验规范化目标、链接和目录归属。

### 10.2 上游升级与 Patch Queue

1. 固定目标官方版本、平台、架构、下载来源和校验值，保留许可文件。
2. 用该版本生成协议，比较必需接口和默认行为；最新网页仅供调研，不能替代目标版本契约。
3. 如果存在批准补丁，按 series 顺序重放并执行每个补丁测试；零补丁时不创建空队列。
4. 在隔离数据副本上运行兼容验证，记录模型、系统和工具版本。
5. 无活动执行、备份有效、迁移兼容性明确后才切换；版本不在会话中热替换。
6. 回滚必须同时考虑二进制、产品 schema 和引擎状态兼容性。旧版本无法读新数据时恢复配套快照；升级后的新数据单独保留并告知回滚点，不静默丢弃。

补丁清单最少包含：补丁 ID、顺序、上游 commit/version、原因、触及范围、关联测试、审核记录、上游链接、移除条件。不能用关闭错误检查、自动提权或复制业务模块的补丁掩盖接入缺陷。

首版人工选择经过共同验证的产品与引擎版本组合更新，不提供绕过产品兼容门禁的独立引擎自动升级，也不建设无人值守更新服务。签名与远程发布另获批准，文档不代表分发已完成。

## 11. 日志、隐私与能力门禁

日志保存脱敏时间、进程归属、版本、connectionEpoch、操作 ID、任务与轮次关联、阶段、错误码及必要根因。默认不保存完整模型请求、环境变量、Key、浏览器 cookie 或办公正文；原始执行历史由引擎管理，其敏感性必须在数据说明中披露。

能力采用“未配置、检查中、可用、不可用、待重新验证”管理，记录依据和实际版本。引擎握手成功不代表模型、沙箱或工具全部可用；不能用单一绿色“服务正常”覆盖全部组件。

关键门禁与证据格式见[兼容性验证计划](../plans/AgentX_Compatibility_Validation_Plan.md)。G0/G1 有限结果见[G1 核心报告](../validation/AgentX_Compatibility_Evidence.md#evidence-g1)，首轮 G0 失败仍留档。M1 的真实产品、打包与生命周期证据见[交付说明](../validation/AgentX_M1_Delivery.md)；完整 V1 的全量权限、通用恢复、办公/浏览器/电脑操作尚未通过。M1 不重做整套前置实验，也不等于完整 V1。
